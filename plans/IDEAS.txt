This document is for not-forgetting ideas. Don't assume we want them implemented already. However, you may refer to them or keep them in mind.

SMALL SCREENS

When a device has a small screen, they will not want to use certain functions.
I think we can disable certain functions in that case.
People are likely going to use their phone for playing the music or practicing; not music-editing.

Also, on small screens (especially vertical screens) the layout should be completely different, as currently (in the non-Zen screen) the buttons are all over the place; make them nice vertical rows or something.

As you'd not see much of the backdrop anyway, we probably want a dedicated fullscreen solution.

We will brainstorm this some time.

PERFORMANCE

Give option to pre-calculate (wave forms of notes for) a song and cache them.
Show a pre-processing bar so the user can choose to await the pre-caching before starting.
If the song plays, stop further pre-caching as you'd not want to put the extra strain on the device; pre-caching is specifically to prevent that.
Minify JS and CSS on GitHub deploy.
Should we use GitHub actions on deploy to make the large hole ocarina SVGs?

LAYOUT

Add close-button top-right of the (non-Zen mode) practice/tuner to un-press the practice. This will feel natural/familiar instintively for many users.
It is not clear to the (new) user that they should start playing the song after pressing 'practice'. Can we inform the user either through a microphone icon in the blue button, instead of the note?
I don't know what the (practice) 'history' function does, so I assume the user doesn't either.

OTHERS

Make the 12-hole 'complete' regarding Zelda Ocarina of Time game songs.

When a song 'overwrites' default about tick on/off, that should not change the use-preference. So when switching back to a song without override, whatever the user had as preference is applied. However, clicking the click button during the override changes (or confirms) the user preference.

THEMES

Additional 80s black audio-stack with square-row LED displays. The red understripe for headers can remain the same as other.
Switching between themes in a way that signifies the color theme without showing it in the current theme during normal usage.

Let's add theming (colors/preview/backdrop/...) to both the main page and song-links, that will show up when people paste a link in social media and for web searches.

BUGS

Telephones go to sleep mode (blacking screen) during play; can we keep it active like when playing a youtube video?
Current behavior is a problem for people practicing.

When CSS changes, a deep refresh is needed. Can we version it, just like the app, so it will retrieve the fresh one on releases?

Swing should be disabled (like tempo) when practice is enabled.
